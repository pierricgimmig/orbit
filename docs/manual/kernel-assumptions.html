Kernel and distro assumptions

Orbit does not probe a kernel version and branch. It assumes a Google/Stadia-era Linux userspace and a kernel that still looks like that. Several of those assumptions are now false on stock Ubuntu, Raspberry Pi OS, and this review VM.

This page mixes two kinds of fact. (1) What the Orbit tree does — verified by reading main. (2) What the kernel does on close of a per-CPU uprobe PMU fd — taken from PR #10’s kernel reading and the usual perf_uprobe_destroy path. That kernel path was not re-read from a kernel tree in this review, and no timings were taken here.

There is no kernel version gate

OrbitService logs uname -a and stops there. The only in-tree comment that names a kernel version is KernelTracepoints.h: sched_wakeup dropped the success field in v5.14 (commit 58b9987de86c). Orbit does not read the tail of that struct, so both layouts work. Nothing else checks KERNEL_VERSION.

Uprobe PMU must exist

uprobe_type() in PerfEventOpen.cpp does:

static uint32_t uprobe_type =
    read_uint32_from_file("/sys/bus/event_source/devices/uprobe/type");

That requires CONFIG_UPROBE_EVENTS (and a kernel that exports the uprobe PMU). read_uint32_from_file calls ReadFileToString(...).value() then std::stoul. If the file is missing, this is an exception on first uprobe open — not a structured ErrorsWithPerfEventOpenEvent. This review VM has no such file.

Uretprobe is bit 0 of perf_event_attr.config on that PMU. That ABI has been stable for a long time; Orbit never negotiates it.

Privileges: root and perf_event_paranoid

CPU-wide events (pid=-1) need either root or perf_event_paranoid ≤ 0 (sometimes −1 depending on the event). Integration tests encode that:

  • Most tests: CheckIsRunningAsRoot() or skip.
  • Sampling-only tests: CheckIsPerfEventParanoidAtMost(0).

If opens fail, the user-visible hint is only “did you forget to run as root?”. There is no check of the sysctl before capture, and no attempt to drop to a smaller CPU set or switch to per-thread events.

docs/building_arm64.md suggests sysctl kernel.perf_event_paranoid=-1 as an alternative to root. That is a machine-wide security change; the service still opens CPU-wide mmap/task/sched fds.

Tracefs vs debugfs

GetTracepointId reads only:

/sys/kernel/debug/tracing/events/<cat>/<name>/id

It never tries /sys/kernel/tracing/... (tracefs, the path distributions have used as the primary mount for years). If debugfs is unmounted or not permitted, every tracepoint open fails: sched, task names, GPU, user-selected tracepoints. Sampling and uprobes (PMU path) do not use this helper; they can still work.

KernelTracepoints.h comments also cite the debugfs format files. Packed structs include “reserved” bytes “not documented in the format file” — another layout assumption.

This VM. uname reported Linux 6.12.94+. No /sys/kernel/debug/tracing/events, no /sys/kernel/tracing/events visible to uid 1000, no uprobe_events. A default OrbitService started here would fail the interesting opens and emit ErrorsWithPerfEventOpenEvent — if it got past uprobe_type() without throwing.

cgroup v1 cpuset

GetCpusetCpus reads /proc/<pid>/cgroup, looks for a line containing cpuset: or cpuset,, then reads:

/sys/fs/cgroup/cpuset<path>/cpuset.cpus

That is cgroup v1. On cgroup v2 the file is elsewhere (/sys/fs/cgroup/.../cpuset.cpus without the cpuset controller directory, and the cgroup line format is different). The function returns empty, Startup logs “Could not read cpuset” and uses every CPU from hardware_concurrency(). That is safe (more fds, not fewer) but it is a Stadia-shaped leftover: comments mention /game.

GetNumCores prefers std::thread::hardware_concurrency(), then shells out to nproc. Offline CPUs and container quotas can disagree with the perf CPU index space (0..n-1).

Per-CPU PMU fds and event_mutex

On main, each instrumented function does create_local_trace_uprobe once per CPU (uprobe) and once per CPU (uretprobe). Closing a fd tears down that local probe.

PR #10’s kernel note (not re-verified against a kernel source checkout in this review): perf_uprobe_destroy takes the global event_mutex for the entire close:

  1. uprobe_apply(false)
  2. uprobe_unregister_nosync — VMA walk, dup_mmap_sem + register_rwsem
  3. uprobe_unregister_sync() — RCU tasks-trace and uretprobes SRCU
  4. tracepoint_synchronize_unregister

Newer kernels expose more efficient unregister (batch / nosync variants used by perf and systemd-style tools). Orbit never calls those APIs. The production-quality fix explored in PR #10 is orthogonal and older-kernel-friendly: register each probe once via uprobe_events, open per-CPU fds as PERF_TYPE_TRACEPOINT consumers of that one registration. Sample fds stay 2×F×NCPU; expensive destroys become 2×F.

pid=target, cpu=-1 was measured on that branch as an fd-count experiment and rejected for production (tid semantics, inherit, mmap). The bench is LinuxTracingIntegrationTest.UprobeAttachDetachBench, off unless ORBIT_UPROBE_BENCH=1. Not run here. Do not invent speedup numbers.

Raspberry Pi / ARM64

Cross-compile path is real (docs/building_arm64.md, build_arm_service.sh). Perf register masks exist for ARM64. User-space trampolines do not. GPU AMD tracepoints will not exist. Uprobe PMU availability depends on the Pi kernel config — not guaranteed, not checked.
