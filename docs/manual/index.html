Orbit · Open Runtime Binary Instrumentation Tool

What Orbit is, and how to read this

Orbit is a native sampling + dynamic-instrumentation profiler. The interesting half of the product lives in a privileged collector (OrbitService) that talks to the kernel through perf_event_open. The Qt client is a remote viewer of that stream.

How to use these pages. They are a hosted manual, not a README. Each page names files and functions that exist in this tree. Open the path if you have the repo; you should not need the repo to understand the system. Relative links work as files or as a static site.

Product in one paragraph

The root README.md states the contract: no source change, no rebuild, no relaunch of the target. Sampling finds candidates; dynamic instrumentation records exact function entry/exit as hierarchical timers; scheduling, memory, AMD GPU driver events, Vulkan markers, and optional Python stacks sit on the same timeline. Serialization of a capture is a first-class file format (src/CaptureFile/FORMAT.md, signature ORBT).

Focus has shifted to Linux. Windows local profiling is partial: ETW sampling and context switches exist; dynamic instrumentation does not. A Windows UI can still drive a Linux OrbitService over SSH. That split is real in the code, not just marketing — see src/Service/OrbitGrpcServer.cpp.

What this review actually ran

This VM is Linux 6.12.94+, 4 CPUs, perf_event_paranoid=2, uid 1000. There is no uprobe PMU at /sys/bus/event_source/devices/uprobe/type, and no uprobe_events under tracefs or debugfs. Qt5 is not installed. A full OrbitQt / LinuxTracing build was not attempted. Integration tests and the opt-in uprobe bench from PR #10 were not run. No timings in these pages were measured here.

What was done: read the tree, including src/LinuxTracing/TracerImpl.cpp, PerfEventOpen.cpp, LinuxCaptureServiceBase.cpp, UserSpaceInstrumentation, UI/symbol paths, CI, and the open PR branch cursor/fast-uprobe-stop-a3cf. That branch is not merged into the tree these pages describe.

Do not treat PR #10 as current behavior. On main, stop still closes one uprobe PMU fd per CPU per function, sequentially. The tracefs-once design lives on that branch only. The kernel-assumptions and Linux-tracing pages cover both the historical cost and the proposed fix.
