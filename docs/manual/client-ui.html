Client UI

The client is a Qt5 shell around an immediate-mode-ish OpenGL capture canvas. Almost every product noun — track, hook, preset, sampling report — is a DataView plus a Track plus a pile of state on OrbitApp.

Session setup

src/SessionSetup is the connection dialog: local gRPC, SSH deploy, “connect to this process”. ServiceDeployManager copies OrbitService with SFTP, starts it, tunnels 44765. --nodeploy skips the copy. --process_name auto-selects after connect.

Process list and module list come from ProcessServiceImpl (GetProcessList, GetModuleList, GetDebugInfoFile, GetProcessMemory). The UI does not parse /proc itself when talking to a remote service.

Main window and capture options

OrbitMainWindow persists settings in QSettings, including kDynamicInstrumentationMethodSettingKey. Invalid stored values snap back to user-space instrumentation. The options dialog (src/OrbitQt/CaptureOptionsDialog.cpp) is the real catalog of toggles:

  • Sampling on/off is still partially hidden (TODO(b/198748597) — “Don’t hide samplingCheckBox…”).
  • Unwinding: DWARF vs frame pointers. Wine group box enables only for DWARF.
  • Dynamic method: Orbit (user-space) vs kernel uprobes.
  • Thread state, context switches, GPU driver, memory collection, introspection, API.
  • Stack dump size; thread-state callstack collection + dump size.

Tracepoint picking is behind --enable_tracepoint_feature (default false). Memory warning threshold is behind --enable_warning_threshold. Time-range selection and symbol-store support are also flag-gated defaults-off.

Capture view and tracks

TimeGraph owns layout, timeline, sliders, and TrackContainer / TrackManager. ProcessTimer is still on the UI object (TODO(b/214282122)). Tracks that actually exist as classes:

TrackSource events
SchedulerTrackSchedulingSlice (sched_switch)
ThreadTrackfunction-call timers, samples, thread-state bar, tracepoint bar
GpuTrack / GpuSubmissionTrack / GpuDebugMarkerTrackAMD jobs + Vulkan markers
FrameTrackinstrumented function used as a frame delimiter
SystemMemoryTrack, CGroupAndProcessMemoryTrackmemory sampling
PageFaultsTrack (major/minor)page-fault series
VariableTrack, AsyncTrackAPI value tracks / async scopes

TrackManager::GetOrCreateTrackFromTimerInfo is the factory from a TimerInfo. Visible-track sort prefers tracks that have instrumented timers. There is a long tail of TODOs around track hierarchy, creating tracks only while drawing, and float time-axis precision (b/244736453).

Thread tracks show samples as ticks and dynamic calls as nested boxes. Filtering of timers is implemented only on ThreadTrack (b/179225487).

Symbols tab and Functions tab

After connect, modules appear in the Symbols data view. SymbolLoader::RetrieveModuleAndLoadSymbols fills them (see symbols). Successfully loaded symbols populate FunctionsDataView.

Columns: Hooked, Function, Size, Module, Address in module. Type glyphs include MS/MA (manual sync/async) and D (dynamically instrumented in the last capture). Hook/Unhook and frame-track enable live in the shared DataView context menu and also appear on sampling-report and callstack views so you can hook from a sample.

Sampling report and call tree

Selecting a range on the sampling track builds a SamplingReport (src/OrbitGl/include/OrbitGl/SamplingReport.h). Call tree widgets (CallTreeWidget, CallTreeViewItemModel) default to fully expanded in this fork (recent commit “Make CallTree Widgets fully expand by default”). The call-tree slider is also on by default here.

Presets

src/PresetFile plus File → Save Preset. A preset stores hooked function hashes/names per module. Load re-selects via OrbitApp::SelectFunctionsFromHashes / SelectFunctionsByName. This does not persist kernel state; it only restocks the Hook list.

Keyboard (as documented)

The root README is the user-facing map: F5 start/stop, W/S or Ctrl+wheel zoom, Ctrl+right-drag zoom-to-range, Ctrl++/− UI scale, Space = last two seconds. Those bindings live in the Qt/GL event handlers (CaptureWindow.cpp, orbitmainwindow.cpp). This review did not click through a running UI.

Introspection

When enable_introspection is on, OrbitService records its own API events and thread states (pid filter includes the service). The UI can also open an IntrospectionWindow. Useful when stop is slow: you can see the collector burning time in Shutdown if introspection was enabled for that capture.

UI debt that bites users. DoZoom is still a global. Several tracks copy-paste layout hacks (“Track hierarchy refactor, remove hack below”). OrbitApp still owns symbol loading, capture start, hooking, and frame tracks. None of that is broken in the small, but it is why “just add a track type” is expensive.
