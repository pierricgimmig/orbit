TracerImpl · perf_event_open · ring buffers

Linux tracing

All kernel-side capture on Linux is orbit_linux_tracing::TracerImpl. It is one thread that opens a swarm of per-CPU file descriptors, mmaps ring buffers, polls them round-robin, and a second thread that drains a deferred queue in timestamp order.

Lifetime

Tracer::Create (src/LinuxTracing/Tracer.cpp) constructs a TracerImpl. Start spawns run_thread_ on TracerImpl::Run. Stop sets stop_run_thread_ and joins. There is no pause. TracingHandler does not reset the tracer after Stop; the comment in TracingHandler.cpp says the object cannot be reused.

Run calls Startup, starts ProcessDeferredEvents on a side thread, then loops: sleep 5 ms if the last pass saw nothing, otherwise read up to kRoundRobinPollingBatchSize (5) records from each PerfEventRingBuffer. On exit it joins the deferred thread, ProcessAllEvents, then Shutdown.

What Startup opens

TracerImpl::Startup (src/LinuxTracing/TracerImpl.cpp) builds two CPU sets: all_cpus = 0 .. GetNumCores()-1, and cpuset_cpus = GetCpusetCpus(target_pid_) (falls back to all CPUs if the cgroup read fails). It raises RLIMIT_NOFILE to the hard limit because each instrumented function costs two fds per CPU.

OpenUprobes: the fd tax

OpenUprobes and OpenUretprobes iterate cpus and call uprobes_retaddr_event_open / uretprobes_event_open (or the args/retval variants) with pid = -1 and cpu = N.

// TracerImpl::OpenUprobes
for (int32_t cpu : cpus) {
  fd = uprobes_retaddr_event_open(module, offset, /*pid=*/-1, cpu);
  (*fds_per_cpu)[cpu] = fd;
}

That is one uprobe fd and one uretprobe fd per CPU per function:

fds = 2 × F × NCPU   (plus extras if record-stack-on is used)

Each fd is its own perf_event_open of type uprobe (sysfs /sys/bus/event_source/devices/uprobe/type). Bit 0 of perf_event_attr.config selects uretprobe (PerfEventOpen.cpp). Path and file offset go in config1/config2.

Uretprobe fds are committed before uprobe fds (“we support temporarily not having a uprobe associated with a uretprobe but not the opposite”). All fds on the same CPU redirect into one ring buffer via PERF_EVENT_IOC_SET_OUTPUT (OpenRingBuffersOrRedirectOnExisting — note the local typo ring_bugger_fd).

Why pid=-1, cpu=N and not pid=target, cpu=-1. perf_event_open’s pid argument is a tid. A single-task event does not see sibling threads already alive; inherit only covers children created after open; inherit + cpu=-1 cannot mmap a sample ring buffer. Production therefore keeps CPU-wide fds so every thread on every core is visible. That choice is why stop cost scales with core count. Documented in PR #10; not re-measured here.

Ring buffers and records

PerfEventRingBuffer mmaps 1 + 2^n pages (perf_event_open_mmap_ring_buffer). ProcessOneRecord switches on perf_event_header.type: FORK, EXIT, MMAP, SAMPLE, LOST, throttle. Unexpected PERF_RECORD_SWITCH* is logged as error — context switches are taken from sched:sched_switch raw samples, not the software switch records.

ProcessSampleEventAndReturnTimestamp classifies the sample by PERF_EVENT_IOC_ID stream id against a pile of hash sets (uprobes_ids_, uretprobes_ids_, sampling, sched, AMD GPU, …). An ORBIT_CHECK asserts at most one classification matches.

Uprobe samples carry SP, IP, and 8 bytes of user stack (the return address about to be hijacked by the uretprobe). Uretprobe samples are empty unless return-value recording is on (then AX / ARM64 X0).

Ordering: PerfEventProcessor

Records from many buffers are not globally ordered. DeferEvent hands them to a mutex-protected vector; ProcessDeferredEvents moves them into PerfEventProcessor. That class assumes nothing older than kProcessingDelayMs = 333 will still arrive. Older events are dropped and a DiscardedPerfEvent is synthesized. Visitors then run in timestamp order:

  • LostAndDiscardedEventVisitor
  • UprobesUnwindingVisitor — function calls, DWARF/FP unwind, mmap → module update
  • SwitchesStatesNamesVisitor — scheduling slices, thread names, thread states
  • GpuTracepointVisitor — joins the three AMD events into FullGpuJob

Call matching is UprobesFunctionCallManager: a per-tid stack of open functions, popped on exit. Depth is stack.size() - 1. A uretprobe with no matching entry returns nullopt (lost uprobe, or capture started mid-call).

Sampling and unwind

DWARF: stack_sample_event_open copies user regs + stack (default dump size up to kMaxStackSampleUserSize = 65000, a kernel short limit documented in PerfEventOpen.h). Unwind is libunwindstack offline (LibunwindstackUnwinder).

Frame pointers: callchain_sample_event_open uses PERF_SAMPLE_CALLCHAIN plus a small stack/regs dump so LeafFunctionCallManager can DWARF-patch the leaf. exclude_callchain_kernel = true.

When a sample lands inside a uretprobe trampoline, UprobesReturnAddressManager patches the hijacked return address back so the stack looks like the target’s. The same machinery consumes user-space instrumentation trampoline ranges via UserSpaceInstrumentationAddresses.

GPU (AMD only)

OpenGpuTracepoints opens three tracepoints system-wide. GpuTracepointVisitor waits until amdgpu_cs_ioctl, amdgpu_sched_run_job, and dma_fence_signaled share a (context, seqno, timeline) key, then emits one FullGpuJob with a guessed hardware start (max of schedule time and previous dma signal on that timeline). Slack of 1 ms when assigning track depth. No Intel/NVIDIA path exists in this tree.

Python (py-spy)

After kernel setup, if enable_python_profiling is set or IsPythonProcess(pid) is true, PythonSamplingThread::Create attaches via pyspy_new / pyspy_new_with_native (third_party/py-spy-ffi, Rust, Cargo required at build). Detection is a symlink read of /proc/<pid>/exe whose filename contains python or pypy. Period defaults to the native sample period or 100 Hz. Failure to attach is logged; capture continues. CMake skips the FFI if cargo is missing, which then breaks the LinuxTracing link line (target_link_libraries(LinuxTracing PRIVATE pyspy_ffi)) unless that imported target still exists.

What the unit tests cover

LinuxTracingTests (see src/LinuxTracing/CMakeLists.txt) is offline: queues, visitors, unwind fixtures, function-call manager, mmap→module update, GPU visitor. It does not call perf_event_open. Integration coverage is a different binary; see the audit.
