Instrumentation

“Hook” in the UI is not one mechanism. The service picks a dynamic method, then falls back. Manual markers and Python stacks are separate producers that only look like timers in the client.

From Hook to a probe

Right-click Hook is kMenuActionSelect in src/DataViews/include/DataViews/DataView.h. FunctionsDataView marks the row with H. That calls OrbitApp::SelectFunction → DataManager::SelectFunction. Nothing is planted in the target until capture starts.

CaptureClient copies selected functions into CaptureOptions.instrumented_functions (file path, build id, file offset, virtual address, size, name, record-args / record-retval). It requires the method to be kKernelUprobes or kUserSpaceInstrumentation.

The UI default is user-space instrumentation (CaptureOptionsDialog::kDynamicInstrumentationMethodDefaultValue). GGP leftover clients still force kKernelUprobes (src/OrbitClientGgp/ClientGgp.cpp).

Two dynamic methods

Kernel uprobes

Covered on the Linux tracing page. Requirements: CONFIG_UPROBE_EVENTS, the uprobe PMU in sysfs, privileges that satisfy perf_event_paranoid, and a file-backed mapping of the function (Wine PEs often fail this — FindFunctionsThatUprobesCannotInstrumentWithMessages).

Uprobes cannot instrument a function that is not (yet) mapped. The warning text promises automatic instrumentation if the module loads later; that depends on mmap events + the existing fd already covering that file offset for the inode. Newly loaded modules with new paths need new opens; the current Startup path does not re-run OpenUserSpaceProbes mid-capture.

User-space instrumentation

InstrumentationManager::InstrumentProcess (src/UserSpaceInstrumentation/InstrumentProcess.cpp):

  1. Locate liborbituserspaceinstrumentation.so next to OrbitService or in ../lib.
  2. If not already injected, InjectLibraryInTracee (ptrace, allocate, dlopen in the target).
  3. Clone a helper thread in the tracee to run InitializeInstrumentation (machine code in MachineCodeForCloneCall — syscall numbers are x86_64).
  4. For each function: skip the libc blocklist, disassemble with Capstone, emit a trampoline, overwrite the prologue with a jump.
  5. Return trampoline ranges + injected path so LinuxTracing can hide them from unwind.

UninstrumentProcess restores prologues only. The library and trampoline mappings stay in the target for the life of the process / manager.

Blocklisted names (IsBlocklisted) include malloc/free internals, __GI_memcpy (libc jumps into +0x3), pthread cancel helpers, etc. Those fall back to uprobes if the method is user-space and they were still in the options — actually they are skipped during InstrumentProcess and appear in function_ids_to_error_messages, then remain in the filtered-out set only if they succeeded. Failed ids stay in linux_tracing_capture_options and uprobes try them. That is the “slower kernel (uprobes)” message in OrbitApp::OnErrorEnablingUserSpaceInstrumentationEvent / OnWarningInstrumentingWithUserSpaceInstrumentationEvent.

Strict seccomp: AnyThreadIsInStrictSeccompMode can refuse the attach. Hotpatchability is a field on InstrumentedFunction (is_hotpatchable) for the disassembler’s benefit.

ARM64. src/UserSpaceInstrumentation/CMakeLists.txt builds StubArm64.cpp that returns “not supported”. Kernel uprobes do have ARM64 register masks in PerfEventOpen.h. docs/building_arm64.md conflates the two and says “uprobes-based function hooking is not supported on ARM64”. That sentence is wrong: the disabled piece is the trampoline JIT, not the uprobe PMU.

Manual instrumentation (Orbit API)

Headers in src/ApiInterface/Orbit.h. User code instantiates the table with ORBIT_API_INSTANTIATE. CaptureClient::FindApiFunctions looks up versioned OrbitApiGetFunctionTableAddress* symbols in loaded modules. EnableApiInTracee writes function pointers into the target so scopes start emitting. Events arrive through the producer-side socket (src/Api/LockFreeApiEventProducer.h) as API scope / track / string events, not as uprobes.

Frame tracks for manual scopes are still a TODO in FrameTrack.cpp (b/169554463).

Wine / Proton

Wine’s __wine_syscall_dispatcher switches to a different stack. DWARF unwind dies after that frame. OrbitApp implements WineSyscallHandlingMethod:

  • kNoSpecialHandling — do nothing (hidden in some UI builds)
  • kStopUnwinding — default; put the dispatcher in functions_to_stop_unwinding_at
  • kRecordUserStack — also add it to functions_to_record_additional_stack_on so a full stack is snapped before the switch

PE modules mapped anonymously (Wine’s typical .text dance) cannot be uprobe targets; the warning string says so explicitly in LinuxTracingUtils.cpp.

Python

Not dynamic instrumentation. PythonSamplingThread samples interpreter stacks via py-spy FFI and synthesizes callstacks / address infos. Auto-enable if the exe name looks like Python — a process named my-python-wrapper matches; an embedded interpreter in blender does not. python_include_native turns on pyspy_new_with_native.

What “dynamic function calls” means in the UI

A FunctionCall is a closed interval: pid, tid, function id, duration, end timestamp, depth, optional retval, optional six argument registers. Thread tracks draw them as nested timers. Sampling still runs independently; UprobesUnwindingVisitor must patch samples that fall inside an open dynamic frame so the callstack is not a lie.
