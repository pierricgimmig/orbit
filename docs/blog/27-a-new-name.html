A New Name

Orbit is the name of a C++ profiler that Google published in 2020. The program in this repository shares an author with it and almost nothing else: not a line of the service, not the viewer, not the build. Before it goes out as an open-source project it gets its own name, perfr, and this post is the record of what that took and what it deliberately left alone.

On the perfr branch, on top of PR #118. Counts are from the rename script's own report and git status after it ran.

4,400lines changed in 387 files by one script
311paths moved, 31 of them crate directories
1file the script missed, for a reason worth a section
0mentions of the old name left outside the history

Renaming a project is mostly search and replace, and the interesting part is everything that is not. The name was in 372 files: crate names, binary names, two pip packages, eighty-five environment variables and macros, thirty-one C functions, seventeen MCP tools, a shared-memory segment prefix, a Windows pipe name, a settings directory, a log directory, two capture-file suffixes, and 294 copyright lines. It was also in twenty-six blog posts, four essays and every link to github.com/google/orbit, where it has to stay, because those are about the past and the past was called Orbit.

What things are called now

perfr is lowercase everywhere it can be, including at the start of a sentence; Perfr exists only inside identifiers that need PascalCase. The service binary is plain perfr, not perfr-service: the thing you install and run is the project, so it carries the project's name.

The capture suffix is the one place where compatibility came for free. The readers never looked at the file name: a bundle is recognised by its manifest, a stream by its first bytes. So an .orbit.zip saved last month opens in a viewer that only ever writes .perfr.zip, and no code was written to make that true.

One script, three rules, two protections

The pass is a hundred lines of Python over git ls-files. It applies ordered rules: the specific ones first (orbit-service becomes perfr, not perfr-service; pierricgimmig/orbit becomes perfr/perfr; .orbitprofiler becomes .perfr), then the three case rules, ORBIT, Orbit, orbit. The capitalised rule is the only one with judgement in it: Orbit touching another identifier character on either side (OrbitTestRust, FOrbitProfilerModule) is a type name and becomes Perfr; Orbit standing alone is prose and becomes perfr. The same function then renames the paths, so crates/orbit-service/python/orbit_profiler/ lands at crates/perfr/python/perfr/ in one git mv per file.

Two things are protected from the rules before they run. The string google/orbit, because it is someone else's repository and the link would break. And the files that are history: the blog, the four essays at the top of docs/, the rename plan itself, and the license texts under tools/frida/licenses/. The script changed nothing in them, and this post is the only one that knows the new name.

The hand pass afterwards was shorter than feared: eleven places where "an orbit" had become "an perfr"; a test asserting that the glob orbit does not match orbit-service, which after renaming asserted that perfr does not match perfr; a mangled symbol in a doc comment whose length prefix (_ZN12orbit_service) had to become _ZN5perfr; the README sentence that now read "perfr is a re-implementation of perfr"; the site footers' "Original perfr" links; and six mentions of a domain the project never owned, which became "a custom domain".

The file the script skipped

After the pass, cargo check failed in exactly one file, crates/perfr/src/names.rs, on eleven unresolved imports: it still said use orbit_capture::. The script had decided it was binary. Its binary test was the usual one, a NUL byte in the first eight kilobytes, and names.rs has one: a test builds a thread name with an embedded \0 to check that the interner stops at it, and the byte is in the source, not escaped. grep had made the same call weeks earlier, which is why that file was the single "non-text" entry under src/ in the layout survey of post 26, and nobody had asked why.

The fix was to convert that one file explicitly; the lesson is the same as in post 21, that the first few bytes of a file are a guess, and a tool that acts on the guess should say which files it guessed about. The script now prints its skip list.

What did not change

The twenty-six posts before this one keep every word, including orbit-service in their command lines and "Orbit" in their titles, because they describe what was run at the time. Their links to pull requests still point at the old repository. The LICENSE still carries "Copyright 2020 The Orbit Authors" below the new notice: the BSD license on the C++ profiler asks that its copyright line survive in derived work, and the service's logic was ported from it function by function, so it does. And the Unreal plugin, the viewer's wordmark and the favicon show the new name in the old typeface and the old artwork; a logo is a design question, not a rename.

The short version. Orbit was Google's name for a C++ profiler. This is a different program by the same author, so it is now perfr: lowercase, service binary perfr, crates perfr-*, API perfr.h, pip perfr and perfr-api, repository perfr/perfr. One script did 4,400 lines and 311 moves; a hand pass did the sentences a script cannot read; old captures open unchanged; the posts before this one stay as written.
