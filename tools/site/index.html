Orbit

A profiler for native applications. Its mode is dynamic instrumentation coupled with sampling: hook the functions you care about, on a running process, without recompiling, and see every call as a scope on the timeline, with a sampling profile underneath it that says where the rest of the time went. Manual instrumentation is there too, for the scopes only you can name.

Orbit is multi-process and multi-machine: one timeline holds every process you capture, the viewer opens from any machine on the network, and the timeline is laid out by machine so more than one can share it. The service is one static binary for x86-64 and arm64 Linux, with Windows and macOS capture under way; the viewer is this page, on any platform with a browser.

Dynamic instrumentation

Pick a function in the sampling report, or search for it, and hook it: entry and exit become a scope on the thread that called it, with its duration, count and distribution in the Live tab. Kernel uprobes, no rebuild of the target.

Hook from the report →

Sampling

Callstacks at a fixed rate on every thread, DWARF or frame-pointer unwound, symbolized from the binaries and their debug files: flat report, top-down and bottom-up trees, a flame graph, and a report scoped to a time selection, a thread, or every instance of one scope.

Manual instrumentation

One header, one static library, for the scopes only you can name: orbit_start / orbit_stop, async spans, links, values. Rust, C, C++ and Python. Anything that can run a command uses orbit-scope.

Processes, machines, platforms

Every process the service sees, on one timeline with the scheduler under them; a machine row per service, from any host on the network. Linux x86-64 and arm64 today; Windows and macOS capture in progress; the viewer runs wherever there is a browser.
